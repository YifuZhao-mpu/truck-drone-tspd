# LOCKED PROTOCOL — TSP-D sortie-aware ALNS (H1) + design-space map (H2) + time-energy Pareto (H3)

**Status: LOCKED (pre-registration). Committed BEFORE any results exist (commit #1).**
**Date: 2026-06-27. Any change after lock is logged as an amendment with reason.**

This single protocol covers H1 (method backbone), H2 (design-space map), and H3 (time–energy Pareto),
which share one solver. Primary metrics and decision rules are pre-declared below.

---

## 1. Problem definition (fixed)

**TSP-D, minimize makespan** (Agatz, Bouman & Schmidt 2018).
- One truck + one drone (single-drone for H1; m drones for the H2 multi-drone axis).
- Customers C, depot 0. Euclidean distances for both vehicles. Truck speed = 1; **drone speed = α × truck**.
- Drone serves **exactly one** customer per sortie: launch at a node the truck visits → fly to drone customer → rendezvous at a later node the truck visits. Launch/land at **nodes only**.
- **Synchronization:** the vehicle arriving first at the rendezvous node **waits**. Makespan = time both vehicles complete all deliveries and return to depot.
- **Endurance** E = max drone time per sortie (launch→customer→rendezvous flight time ≤ E). E = ∞ allowed as limiting case (Agatz base model).
- Base model (H1): all customers drone-eligible, zero launch/recovery service time (matches Agatz TSP-D so we can validate against published optima/best-known).

## 2. Instances (fixed)

- **Primary (synthetic, Agatz-style):** customers ~ Uniform[0,1]^2, depot at center (0.5,0.5). Sizes n ∈ {10, 20, 50} (+ n=100 exploratory). 30 instances per size, fixed seeds {0..29}. Generated by our `generate.py` (seeds committed) so they regenerate bit-for-bit.
- **External validation (if fetchable):** Agatz/Bouman public instances `github.com/pcbouman-eur/TSP-D-Instances` (uniform, α∈{1,2,3}), and any with published optimal/BKS values (Dell'Amico optima, Roberti–Ruthmair). Used to validate correctness (small-n gap to optimal) and to position vs best-known. If download fails, we compute exact optima ourselves for n ≤ 10 by DP/enumeration as the oracle. **Either way an exact oracle is required for the small-n correctness check.**

## 3. Algorithm (design fixed; implementation details free)

**Solution representation:** a customer permutation ("giant tour") + a mode assignment; decoded by a
**DP optimal split** into a truck route with embedded drone sorties (Agatz/Bouman/Ha split), which
yields the optimal makespan-minimizing partition of the given order into truck nodes vs single-customer
drone sorties. Makespan evaluated by forward simulation with waiting.

**ALNS outer loop** (Pisinger & Ropke 2007 / Sacramento 2019 template) with **adaptive operator weights**
(roulette by recent success), simulated-annealing acceptance:
- **Destroy:** random removal, worst-removal (largest makespan contribution), Shaw/related removal (spatial). [generic]
- **Repair:** greedy insertion, regret-2 insertion. [generic]
- **Sortie-aware operators (the H1 contribution — first-class):**
  1. **launch/rendezvous reassignment** — for an existing drone sortie, re-pick its launch and/or rendezvous truck node to cut waiting/detour.
  2. **drone-customer swap** — swap a drone customer with a nearby truck customer (mode exchange), re-decoding the sortie.
  3. **mode flip** — toggle a customer truck↔drone (make-drone / make-truck).
- Each accepted candidate is re-decoded by DP split; best feasible solution tracked.

**Stopping:** fixed iteration budget per instance (pre-set per size; e.g. 20k–40k iterations or a wall-clock cap), identical across compared methods.

## 4. Baselines (fixed)

1. **Truck-only TSP** — 2-opt + Or-opt local search from nearest-neighbor (the reference for "savings"; this is the no-drone world). [also the H2 denominator]
2. **Greedy TSP-LS** — Agatz-style: build TSP tour, greedily convert customers to drone sorties (no metaheuristic). Lower bar.
3. **Generic-ALNS ablation** — identical ALNS WITHOUT the three sortie-aware operators (only generic destroy/repair + mode flip). [isolates the H1 operator contribution]
4. **Exact optimum** (n ≤ 10) / **published best-known** — correctness + positioning.

## 5. Pre-declared metrics

- **Primary (H1):** mean **optimality/BKS gap %** = (makespan − ref)/ref × 100 on uniform instances, with ref = exact optimum (n≤10) or best-known/strong reference. Secondary: gap of sortie-aware ALNS vs generic-ALNS ablation (the **operator-necessity delta**, paired per instance), runtime, feasibility (100% by construction).
- **Primary (H2):** **% makespan saving vs truck-only TSP** = (truck_only − tsp_d)/truck_only × 100, as a function of (α, E, m). Decision: surface must be **monotone non-decreasing and concave (diminishing returns)** in each axis and lie **below** the ceiling 1−1/(αm+1); report saturation knees. Single-drone α=2 saving compared to the ~30% asymptotic reference.
- **Primary (H3):** the **makespan vs total drone-energy Pareto front** (non-dominated set over λ sweep). Decision: front is **non-degenerate** (time-opt and energy-opt solutions differ by a pre-set margin, e.g. ≥5% on each axis) and exhibits a **knee** (a point where a ≤X% makespan increase buys a ≥Y% energy cut). If time-opt ≈ energy-opt, H3 **refuted**.

## 6. Experimental grid

- **H1:** n ∈ {10,20,50} (+100 exploratory) × {sortie-aware ALNS, generic-ALNS, greedy, truck-only, exact/BKS}. 30 instances/size. **3 random seeds** for the stochastic ALNS; report mean ± std and paired sortie-vs-generic comparison (sign test / per-instance paired deltas).
- **H2:** α ∈ {1, 1.5, 2, 2.5, 3} × E ∈ {0.5, 1.0, 2.0, ∞} (normalized to instance scale) × m ∈ {1, 2, 3}. Fixed instance set (n=20 confirmatory; n=50 confirmatory subset). Metric = mean % saving vs truck-only. Multi-drone (m>1) uses parallel single-customer sorties on the one truck (mFSTSP-style); honestly flagged as a heuristic extension.
- **H3:** energy model = Dorling-type affine power-in-payload, E_leg = (a·m_payload + b)·(dist/speed); truck energy ∝ distance. Optimize makespan + λ·drone_energy, λ swept over ≥8 values incl. 0 and large; n=20/50; build Pareto, locate knee.

## 7. Statistical analysis & bias mitigation

- **Confirmatory:** H1 main gaps + operator-necessity delta (n=10/20/50); H2 surface monotonicity/concavity (n=20, n=50 subset); H3 Pareto non-degeneracy (n=20/50).
- **Exploratory:** n=100; α/E off-grid points; any post-hoc slices. Labeled as such.
- Multiple seeds (≥3) for all stochastic results; report mean ± std. Paired per-instance comparisons for ablations (avoid instance-difficulty confound). Identical iteration/time budget across compared methods (fair tuning budget). Multiple-comparison awareness: H2 grid is a surface, reported as a map, not N independent significance tests.
- **Reward null results:** if sortie operators don't help, or the surface isn't concave, or the Pareto is degenerate, that is logged as a valid finding, not hidden.

## 8. Falsification (what would refute each hypothesis)

- **H1 refuted** if sortie-aware ALNS does NOT beat the generic-ALNS ablation (paired), OR fails to match exact optima on n≤10 (a correctness bug), OR gap to best-known is not "competitive" (pre-set: > ~5–8% on uniform n=20/50 with the chosen budget).
- **H2 refuted** if savings are NOT diminishing-returns / not concave, or exceed the worst-case ceiling (would indicate an evaluation bug), or show no identifiable saturation.
- **H3 refuted** if the makespan-optimal and energy-optimal solutions coincide (no real trade-off / degenerate front).
